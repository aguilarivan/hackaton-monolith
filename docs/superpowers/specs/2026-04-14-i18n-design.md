# i18n Design — Spanish + English Toggle

**Date**: 2026-04-14
**Status**: Approved
**Scope**: Add full internationalization with a language toggle to Day Zero (currently Argentine Spanish only)

## Overview

Add English as a second language to the Day Zero app using `next-intl`, with URL-prefix-based routing, a header toggle, and locale-aware AI content generation. Spanish remains the default locale with clean (unprefixed) URLs.

## Languages

- `es` — Argentine Spanish (default, no URL prefix)
- `en` — English (URL prefix `/en/`)

## 1. Routing & Middleware

### Route structure

All existing pages move under an `app/[locale]/` dynamic segment:

```
app/
  [locale]/
    page.tsx
    login/page.tsx
    preguntas-claude/page.tsx
    analisis/page.tsx
    layout.tsx
```

### Middleware (`middleware.ts`)

- Reads URL for locale prefix
- No prefix → defaults to `es`
- `/en/...` → serves English
- Sets a cookie so `next-intl` remembers preference across visits
- Does NOT auto-redirect based on `Accept-Language` header

### Config (`i18n/config.ts`)

```ts
export const locales = ['es', 'en'] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = 'es';
```

## 3. Component Integration

### Server components (pages, layouts)

Use `getTranslations()`:

```tsx
const t = await getTranslations('analysis');
return <h1>{t('title')}</h1>;
```

### Client components (interactive: header, hero-input, etc.)

Use `useTranslations()` hook:

```tsx
const t = useTranslations('common');
return <button>{t('newIdea')}</button>;
```

### Locale-aware formatting

Replace hardcoded `"es-AR"` in `.toLocaleString()` calls with the current locale from `useLocale()` or the route param. Use `next-intl`'s `useFormatter()` for numbers, dates, and currency where appropriate.

### Metadata

`generateMetadata()` in the `[locale]/layout.tsx` reads the locale param and returns translated title and description. The `<html lang>` attribute is set dynamically from the locale.

## 4. Language Toggle

A button in the header, next to the existing theme toggle:

- Displays "EN" when the app is in Spanish (switch to English)
- Displays "ES" when the app is in English (switch to Spanish)
- Uses `next-intl`'s `useRouter()` and `usePathname()` to navigate to the same page in the other locale
- Preserves query params and scroll position where possible

## 5. AI-Generated Content Localization

### System prompts

Prompt builder functions (`analysis-prompt.ts`, `questions-prompt.ts`, `section-plan-prompt.ts`) receive the locale as a parameter and adjust the language instruction:

```ts
export function buildAnalysisPrompt(input: BusinessInput, locale: string) {
  const lang = locale === 'en' ? 'English' : 'Argentine Spanish';
  return `Respond entirely in ${lang}. ...`;
}
```

### Mock data

`generateAnalysis()` in `lib/mock-data.ts` receives the locale and selects from parallel string templates (Spanish and English) for all synthetic analysis content.

### Flow record

`FlowRecord` gains an optional `locale` field so the session remembers which language the user started in. This ensures analysis generation uses the correct language.

## 6. API Layer

### Error messages

API routes receive the locale via an `X-Locale` request header set by the client-side fetch layer. Error messages returned by `apiError()` are selected based on this header.

### Client (`lib/flow-api.ts`)

The `requestJson` helper reads the current locale and passes it as an `X-Locale` header on every request.

## 7. Client-Side Persistence & Navigation

### Locale preference

Stored in `next-intl`'s cookie (set by middleware). NOT stored in localStorage alongside the `dayzero.*` namespace.

### Navigation redirects

Existing "redirect to `/` if no active session" logic becomes locale-aware — redirects to `/${locale}` instead of `/`. Uses `next-intl/navigation`'s router/redirect.

### Link components

All `<Link>` usages switch to `next-intl`'s `Link` export, which automatically prepends the current locale prefix. Internal `href` values stay as-is (e.g., `href="/analisis"`) — the library handles prefixing.
